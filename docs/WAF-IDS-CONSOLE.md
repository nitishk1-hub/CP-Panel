# Native WAF and IDS

The current web provider is native Coraza/Caddy with OWASP CRS. Suricata is a separate constrained native IDS service. Security Center stores normalized events in a dedicated private PostgreSQL database. BunkerWeb deployment/console notes are historical; retired vendor credential endpoints remain unavailable.

Core installation does not provision these engines. The explicit security profile provisions the private event database, verified Coraza build, Suricata/rules, local routing helper and audit rotation. It starts prevention/capture off. Configured CrowdSec and local GeoIP remain optional; missing CrowdSec must not halt unrelated Coraza/Suricata event ingestion. No vendor console account is generated by the current Coraza provider.

The stable local entry is 127.0.0.1:18180 and Coraza normally binds 127.0.0.1:19180. A separately selected origin must avoid recapture; the native Nginx profile uses 127.0.0.2:80. Docker bridge origins are topology-specific, not universal defaults. Loopback OUTPUT NAT covers only the selected local IPv4 path. Public listeners, direct Docker ports, IPv6 and TLS traffic outside that route require separate bypass/coverage tests.

Off bypasses inspection for new routed connections and stops capture/response. Monitor records matched requests without the blocking policy. Block enables verified routed WAF enforcement and the configured timed response behavior. Suricata remains passive unless a separately qualified inline path exists. Mode transitions snapshot web policy, IDS state, response state and routing; compensation failures remain visible rather than being reported as a successful rollback. Provider failure uses availability-first ingress bypass; operators must observe this degraded state.

The current proxy identity profile trusts loopback for CF-Connecting-IP, assuming trusted local proxy processes overwrite that header correctly. Do not enable source-IP remediation on a different topology without spoofing tests and management exemptions. Encrypted contents, offload, capture drops and interface changes limit visibility. Locations are approximate source-IP geolocation, not verified physical attacker locations.

Event retention is configurable from 1 to 90 days; short-lived telemetry has a separate retention setting. Database capacity thresholds pause collection while engines continue independently. Partition cleanup and physical disk reclamation require load/maintenance qualification. Panel audit logs rotate by size and return bounded tail reads. Coraza audit logs use a dedicated size-based rotation policy checked every five minutes; copytruncate can lose records during rotation and is not a hard filesystem quota. Monitor disk capacity, journal retention and event loss separately.

Back up private configuration, event data with PostgreSQL-consistent tools and external website/application state using a tested procedure. Ordinary application/OS vulnerabilities are not repaired merely by adding WAF/IDS. Real install, restart, failure recovery, bypass, spoofed-header and representative load tests remain release gates.
